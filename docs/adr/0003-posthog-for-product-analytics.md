# 사용자 행동 기록은 PostHog 하나로 하고, GA4는 광고를 시작할 때 소개 페이지에만 붙인다

꼬박은 모든 기능을 가설로 세우고 사용자 행동으로 판정한다(`docs/planning/hypotheses.md`). 판정·이의 제기·정산에서 나오는 숫자(H1, H3, H4, H5)는 서버 DB에 이미 있으므로 SQL로 본다. 서버가 모르는 행동(초대 웹 화면을 열고 떠남, 공유 카드를 보고 들어옴, 화면 이탈 지점)은 PostHog로 앱과 웹을 함께 기록한다(2026-11-27, 사용자 결정). PostHog는 매달 100만 건까지 무료이고 Expo가 공식으로 연동을 안내하며, 퍼널·화면 녹화·기능 켜고 끄기를 한 도구에서 준다.

## Considered Options

- PostHog와 GA4를 함께 쓰기: 같은 행동을 두 번 기록해야 하고, 두 도구가 사용자를 세는 방식이 달라 같은 퍼널의 숫자가 다르게 나온다. 가설 판정 기준은 하나여야 해서 고르지 않았다.
- 자체 DB에만 기록: 웹과 앱을 오가는 흐름과 화면 이탈을 직접 만들어야 해서 고르지 않았다.
- GA4: 광고·검색 유입 분석이 강점이지만, 그룹 단위 유지율이나 퍼널을 자유롭게 짜기 어렵다. 광고를 돌리기 시작하거나 소개 페이지 검색 유입을 키울 때 소개 페이지(Next.js)에만 GTM으로 붙인다. 역할은 "GA4는 들어오기 전, PostHog는 들어온 뒤"로 나눈다.

## Consequences

- 사용 한도를 0원으로 걸어 무료 범위를 넘어도 돈이 나가지 않게 한다.
- PostHog 클라우드는 해외 서버라 개인정보처리방침에 국외 이전을 적는다. 닉네임 같은 개인정보는 보내지 않고 내부 회원 번호로만 기록한다.
- 기록할 행동은 기능의 티켓 안에서 함께 만든다(`docs/engineering/work-pipeline.md` 1절).
