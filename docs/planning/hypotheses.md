# 기능 가설 목록

마지막 수정: 2026-11-27
상태: 가설 내용은 **권장**(승인 필요). 가설을 세우고 검증하는 방식 자체는 사용자 요청으로 확정(2026-11-27).

꼬박의 모든 기능은 가설에서 출발한다. 기능을 만들고, 사용자가 써 본 기록으로 가설이 맞는지 판정한다. 판정 결과에 따라 키우거나, 고치거나, 지운다. 진행 방식은 [work-pipeline.md](../engineering/work-pipeline.md) 1절에 있다.

## 판정할 때 주의할 점
- 첫 목표가 가입자 100명이라 그룹은 많아야 15~25개다. 둘로 나눠 비교하는 실험(A/B 테스트)은 숫자가 너무 작아 결론을 내기 어렵다.
- 그래서 판정은 **미리 정한 기준선을 넘는지**로 한다. 기준선은 출시 전에 정하고, 결과를 본 뒤에 바꾸지 않는다.
- 숫자와 함께 이유를 본다. 그룹이 깨지거나 기능을 안 쓰면, 그룹장에게 짧게 묻거나 이의 제기 내용을 읽어 이유를 기록한다.
- 기준선을 못 넘었다고 바로 지우지 않는다. "다른 설명"부터 확인한다.

## 가설 카드 형식
| 칸 | 내용 |
|---|---|
| 가설 | 우리는 [누가]가 [무엇을 하면] [어떤 결과]가 생긴다고 믿는다. 왜냐하면 [작동 방식] 때문이다 |
| 근거 | 지금 있는 근거와 그 강도 |
| 다른 설명 | 결과가 나와도 이 기능 때문이 아닐 수 있는 이유 |
| 측정 | 분자, 분모, 기간. 기록해야 할 사용자 행동 |
| 기준선 | 맞다고 볼 숫자, 틀렸다고 볼 숫자 |
| 보조 지표 | 숫자만 오르고 사용자 경험이 나빠지는 것을 막는 지표 |
| 판정 시점 | 언제 본다 |
| 맞으면 / 틀리면 | 할 일 |

## 첫 버전 가설

### H1. 자동 집행이 그룹을 오래 가게 한다 (핵심)
| 칸 | 내용 |
|---|---|
| 가설 | 벌금 스터디 그룹은 인증 확인, 판정, 장부를 꼬박이 자동으로 하면 4주 뒤에도 인증을 이어 간다. 왜냐하면 지금 그룹이 깨지는 주된 이유가 사람이 하는 총무 일이기 때문이다 |
| 근거 | 공개 모집글의 담당 교대 규칙, 노션 벌금 템플릿 판매, 미납·탈퇴 다툼 후기 (관찰, 사례 수 적음) |
| 다른 설명 | 시험이 끝나 자연스럽게 해산한다. 지인 테스트 그룹이라 원래 친해서 오래 간다 |
| 측정 | 4주 유지 그룹 비율 (planning.md 1-2장의 정의) |
| 기준선 | 50% 이상이면 맞음, 30% 미만이면 틀림. 실제 벌금 스터디의 유지율 자료는 없어서 첫 기준선은 추정이다 |
| 보조 지표 | 그룹장 업무량(그룹당 주간 수동 조작 수), 벌금 때문에 나간 비율 |
| 판정 시점 | 운영 4주차, 8주차 |
| 맞으면 / 틀리면 | 정산·탈퇴 기능을 다듬는다 / 그룹이 깨진 이유를 모아 핵심 문제 가설을 다시 세운다 |

### H2. 규칙 카드가 참여를 늘리고 다툼을 줄인다 (스펙 #1)
| 칸 | 내용 |
|---|---|
| 가설 | 초대 링크를 연 사람은 돈 규칙이 담긴 규칙 카드를 보면 망설이지 않고 참여한다. 그리고 중간 탈퇴 때 돈 다툼이 줄어든다. 왜냐하면 다툼이 주로 미리 합의하지 않은 돈 규칙에서 생기기 때문이다 |
| 근거 | 탈퇴 시 보증금 다툼 후기 (관찰) |
| 다른 설명 | 지인이 보낸 링크라 규칙과 상관없이 참여한다 |
| 측정 | 초대 링크 연 사람 중 참여한 비율. 중간 탈퇴 중 이의·문의가 생긴 비율 |
| 기준선 | 참여율 40% 이상이면 맞음, 20% 미만이면 틀림. 탈퇴 관련 문의 0~1건 |
| 보조 지표 | 참여 후 7일 안에 나간 비율 |
| 판정 시점 | 운영 4주차 |
| 맞으면 / 틀리면 | 규칙 카드를 모집글용 이미지로도 만든다 / 규칙 카드에서 사람들이 멈추는 곳을 찾는다 |

### H3. AI 확인이 충분히 정확하다
| 칸 | 내용 |
|---|---|
| 가설 | AI가 템플릿 기본 기준과 그룹 기준 문장으로 인증 사진 대부분을 바로 판정한다. 왜냐하면 공부·독서·운동 사진은 무엇이 찍혔는지가 분명하기 때문이다 |
| 근거 | 아직 없음. 출시 전에 사진 50장으로 시험한다 |
| 다른 설명 | 그룹원끼리 봐줘서 이의 제기가 적을 수 있다 |
| 측정 | AI "애매" 비율, 이의 제기 비율, 이의 제기 중 인정된 비율(= AI 오판) |
| 기준선 | 오판 5% 이하면 맞음, 10% 초과면 틀림 |
| 보조 지표 | 이의 제기 후 그룹을 나간 비율 |
| 판정 시점 | 출시 전 50장 시험, 운영 2주차 |
| 맞으면 / 틀리면 | 그대로 둔다 / 기준 문장을 고치거나 모델을 바꾼다. 그래도 안 되면 그룹원 확인을 기본으로 바꾼다 |

### H4. 쉬는 날과 복귀 축하가 첫 결석 뒤 포기를 막는다
| 칸 | 내용 |
|---|---|
| 가설 | 결석한 멤버는 다음 날 복귀를 축하받으면 이틀 연속 빠지지 않는다. 왜냐하면 첫 실패가 포기로 이어지는 것은 "이미 망쳤다"는 느낌 때문이기 때문이다 |
| 근거 | 헬스장 대규모 실험(54개 방법 중 복귀 보상 1위), 연속 기록 연구 (외부 연구) |
| 다른 설명 | 원래 성실한 사람만 복귀한다 |
| 측정 | 결석 다음 인증일에 인증한 비율(복귀율) |
| 기준선 | 60% 이상이면 맞음, 40% 미만이면 틀림 |
| 보조 지표 | 쉬는 날을 다 쓴 비율 (너무 높으면 벌금 압력이 약해진 것) |
| 판정 시점 | 운영 4주차 |
| 맞으면 / 틀리면 | 주간 시즌(새 출발)을 붙인다 / 복귀 알림 문구와 시점을 바꾼다 |

### H5. 그룹이 정산표대로 실제로 정산한다
| 칸 | 내용 |
|---|---|
| 가설 | 기간이 끝난 그룹은 꼬박 정산표대로 돈을 주고받고 정산 완료를 표시한다. 왜냐하면 계산이 끝나 있으면 송금만 하면 되기 때문이다 |
| 근거 | 실제 스터디가 이미 모임통장으로 직접 정산한다 (관찰) |
| 다른 설명 | 정산은 했지만 앱에 표시하지 않는다 |
| 측정 | 종료된 그룹 중 7일 안에 모든 멤버가 정산 완료된 비율 |
| 기준선 | 60% 이상이면 맞음, 30% 미만이면 틀림 |
| 판정 시점 | 첫 기간이 끝나는 그룹이 5개 이상 생겼을 때 |
| 맞으면 / 틀리면 | 그대로 둔다 / 정산 완료 표시를 멤버 스스로 하게 바꾸거나, 표시 없이도 정산표만 남긴다 |

### H6. 인증 카드 공유가 새 그룹을 데려온다
| 칸 | 내용 |
|---|---|
| 가설 | 멤버가 인증 카드를 SNS에 공유하면 그것을 본 사람이 새 그룹을 만든다. 왜냐하면 공부 인증을 올리는 사람들 주변에 같은 습관을 가진 사람이 많기 때문이다 |
| 근거 | 행동 확산 연구, Wordle 공유 사례 (외부) |
| 다른 설명 | 새 그룹은 공유가 아니라 지인 홍보로 들어온다 |
| 측정 | 공유 1건당 공유 링크를 통한 가입 수, 그중 그룹을 만든 수 |
| 기준선 | 공유 20건당 새 그룹 1개 이상이면 맞음 |
| 판정 시점 | 운영 4주차 |
| 맞으면 / 틀리면 | 한 주 격자 공유를 키운다 / 공유 기능을 줄이고 그룹장 홍보에 힘을 쓴다 |
