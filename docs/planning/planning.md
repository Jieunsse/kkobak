마지막 수정: 2026-11-26
상태 표시: 확정(사용자가 승인) / 권장(추천, 미승인) / 가설(검증 안 된 원인 해석) / 미결정 / 충돌 / 외부 검증(확인이 필요한 주장) / 대체됨

## 1. 문제정의 브리핑 (problem-definition 형식)

### 입력된 주제
벌금 스터디처럼 소규모 그룹이 매일 인증하는 약속을, 기간 끝까지 지키게 돕는 앱 "꼬박"

### 핵심 결론
벌금 스터디가 깨지는 이유는 멤버의 게으름보다 **총무 일**에 가깝다. 인증 확인, 판정, 벌금 계산, 정산 안내를 사람이 손으로 해서, 담당자가 지치거나 돈 문제로 다투면 그룹이 깨진다. 꼬박은 습관 앱이 아니라 **돈은 맡지 않는 스터디 총무**가 되어야 한다. (가설, 근거는 공개된 실제 행동 기록)

### 현재 상황
공개 모집글 10건 중 8건에 벌금이 있다. 규칙은 정교하다. 그런데 체크, 계산, 송금 독촉은 사람이 한다. 그래서 "출석 체크 담당을 매주 돌린다"는 규칙이 따로 생기고, 벌금 계산용 노션 템플릿을 돈 주고 산다.

| 항목 | 실제로 본 것 |
|---|---|
| 마감 | 기상 스터디는 9:00~9:30, 공부 스터디는 23:59. 새벽 1시까지 유예를 주는 곳도 있다 |
| 지각 | 9:00까지는 정상, 9:30까지는 지각으로 나눠 벌금을 다르게 매긴다 |
| 사진 조작 방지 | 타임스탬프 앱 사용, 찍고 5분 안에 올리기, 간판이나 야외가 보이게 찍기 |
| 벌금 | 하루 500원~4,000원 |
| 돈 관리 | 보증금을 미리 받아 모임통장에 모으거나, 그날그날 방장에게 이체한다 |
| 정산 | 성적 상위자끼리 나누기, 전원 1/N 환급, 뒤풀이 비용, 보증금에서 빼고 돌려주기 |
| 예외 | 면제권 또는 패스권. 미리 알려야 쓸 수 있다. 시험이나 질병은 증빙을 내면 면제 |
| 운영 | 출석 체크와 정산 담당을 매주 돌린다. 점수표를 시트로 공유한다 |

출처: [인프런 스터디 443497](https://www.inflearn.com/studies/443497), [링커리어 6212601](https://community.linkareer.com/recruit_study/6212601), [링커리어 6268302](https://community.linkareer.com/recruit_study/6268302), [인프런 스터디 854545](https://www.inflearn.com/studies/854545) 외. 네이버 카페, 에브리타임, 오픈채팅 글은 접근하지 못했다.

### 영향을 받는 사용자 (역할별)
| 역할 | 누구 | 해내려는 일 | 지금 떠안는 비용 | 꼬박이 주는 것 |
|---|---|---|---|---|
| 도입을 결정하는 사람 | 방장 (모집글을 쓰고 규칙을 정함) | 스터디를 끝까지 굴리기 | 체크, 계산, 독촉, 다툼 중재. 가장 큰 비용을 진다 | 총무 일이 사라진다 |
| 쓰는 사람 | 멤버 | 목표를 지키고, 억울한 벌금은 피하기 | 매일 사진 올리기, 억울한 판정, 돈 다툼 | 인증만 하면 나머지는 자동이다 |
| 돈을 맡는 사람 | 모임통장 주인 (대개 방장) | 돈을 투명하게 관리하기 | 미납 독촉, 탈퇴자 환급 계산 | 누가 누구에게 얼마인지 정산표가 나온다 |
| 운영하는 사람 | 꼬박 (나) | 서비스 운영 | AI 비용, 이의 제기와 문의 응대 | 해당 없음 |

**제품에 주는 의미**: 앱을 쓸지 정하는 사람은 멤버가 아니라 방장이다. 그래서 홍보 대상, 첫 화면, 그룹 만들기 흐름은 방장 기준으로 설계한다. (확정)

### 현실과 목표의 괴리
- **현실**: 방장은 규칙을 정한 뒤에도 매일 확인하고 계산하고 독촉해야 한다. 돈 규칙은 말로만 합의되어 있어서 탈퇴나 미납 때 다툼이 생긴다.
- **목표**: 방장은 규칙만 정한다. 멤버는 인증만 한다. 확인, 판정, 계산, 정산 안내는 처음에 합의한 규칙대로 자동으로 된다.
- **괴리**: 규칙은 있는데 집행하는 주체가 사람이다.

### P코드 (증상, 목표, 제약, 원인 후보)
| 코드 | 종류 | 내용 | 근거 |
|---|---|---|---|
| P1 | 증상 | 출석 체크와 벌금 계산을 사람이 매일 손으로 한다. 그래서 담당을 매주 돌린다 | 관찰: 모집글 2, 3, 4번 |
| P2 | 증상 | 이 일을 덜려고 벌금 계산용 노션 템플릿을 돈 주고 산다 | 관찰: [노션박스](https://notionbox.kr/template/product/group_study) |
| P3 | 증상 | 벌금 미납자를 독촉하기 어렵고, 결국 스터디가 없어진다 | 관찰: [코스모폴리탄](https://www.cosmopolitan.co.kr/article/25794) |
| P4 | 증상 | 중간에 나갈 때 보증금과 결석비를 두고 다툼이 생긴다 | 관찰: [인스티즈](https://www.instiz.net/name/30004567) |
| P5 | 증상 | 사진 조작을 막는 규칙이 복잡하고, 그래도 뚫린다 | 관찰: 모집글 규칙, 열품타 시간 부풀리기 |
| P6 | 증상 | 규칙이 너무 빡빡하면 모두 벌금만 내다 그만둔다 | 관찰: [velog 후기](https://velog.io/@jaedup/싸피에서-알고리즘-스터디-만들기-간단-후기) |
| P7 | 목표 | 그룹이 정한 기간 끝까지 모두가 약속을 지킨다 | 추정 |
| P8 | 제약 | 친구나 지인 사이라 돈 독촉이 관계를 상하게 한다 | 관찰: P3, P4 사례 |
| P9 | 제약 | 꼬박은 돈을 맡을 수 없다 (사업자, 금융 규제) | 확정 |
| P10 | 원인 후보 | 규칙 집행을 사람이 한다 | 가설 |
| P11 | 원인 후보 | 돈 규칙이 시작 전에 명확히 합의되지 않는다 | 가설 (P4 근거) |
| P12 | 원인 후보 | 규칙이 한 번의 실패에 너무 가혹하다 | 가설 (P6 근거) |

### R코드 (증상만 줄이는 지금의 대응)
| 코드 | 대응 | 줄여 주는 것 | 남는 문제 | 부담이 옮겨 가기만 하는가 |
|---|---|---|---|---|
| R1 | 담당을 매주 돌리기 | 한 사람에게 일이 몰리지 않는다 | 일의 총량은 그대로다 | 예. 방장에서 멤버 전원으로 옮겨 간다 |
| R2 | 노션 벌금 템플릿 | 계산을 조금 줄인다 | 기간을 바꾸면 손으로 고쳐야 하고, 인증 확인은 사람이 한다 | 일부 |
| R3 | 타임스탬프 앱, 5분 규칙 | 옛날 사진 재사용을 줄인다 | 사람이 사진을 하나하나 봐야 한다 | 아니오, 하지만 확인 일은 남는다 |
| R4 | 보증금 + 모임통장 | 미납을 미리 막는다 | 탈퇴 시 환급 계산과 다툼은 남는다 | 일부 |
| R5 | 회사에 돈 걸기 (챌린저스) | 압력이 강하다 | 개인용이다. 판정 기준 다툼이 잦았다. 지금은 쇼핑 앱으로 중심을 옮겼다 | 해당 없음 |
| R6 | 열품타 그룹 미션 | 공부 시간이 자동 기록된다 | 벌금 계산과 정산은 확인 못 함. 공부 외 주제는 약하다 | 확인 필요 |

### 킹핀 후보
- **KP-1 ⋅ 킹핀 후보 (핵심 문제)**: 그룹이 정한 규칙을 집행하는 일(확인, 판정, 계산, 정산 안내)을 사람이 손으로 한다. 그래서 담당자가 지치거나 돈 문제로 다투면 규칙이 무너지고 그룹이 깨진다.
- **KP-2 ⋅ 킹핀 후보**: 규칙이 한 번의 실패에 너무 가혹해서, 첫 실패가 포기로 이어진다.

### 킹핀 선정 근거 (KP-1)
| 기준 | 통과 | 이유 |
|---|---|---|
| 여러 증상을 설명하는가 | 통과 | P1~P5를 설명한다 |
| 현실과 목표의 괴리를 설명하는가 | 통과 | 괴리가 "집행 주체가 사람"이라는 점이다 |
| 눈에 보이는 증상보다 구조적인가 | 통과 | 담당 교대나 템플릿 구매는 이 구조의 결과다 |
| 범위 안에서 손대고 시험할 수 있는가 | 통과 | 자동화 후 4주 유지율과 방장 수작업 횟수로 시험할 수 있다 |
| 원하는 해결책 이름을 바꿔 말한 것이 아닌가 | 주의 | "자동화가 필요하다"로 읽히면 해결책을 되풀이한 것이다. 그래서 원인을 "집행 주체가 사람"으로 적었다 |

KP-2는 P6 하나만 설명한다. 그래서 KP-1을 핵심으로 두고 KP-2는 보조 후보로 둔다.

### 문제 정의문
> 벌금 스터디를 운영하는 방장과 멤버는 몇 주 동안 매일 인증하는 스터디에서 모두가 기간 끝까지 약속을 지키려 하지만, 규칙의 확인, 판정, 계산, 정산 안내를 사람이 손으로 해야 하는 구조 때문에 담당 교대, 미납 독촉, 정산 다툼, 중도 해체를 반복해서 겪는다.

### 해결책 (S코드)
```
KP-1
→ 바꿀 조건: 규칙 집행의 주체를 사람에서 시스템으로 바꾼다. 돈은 그룹이 계속 직접 관리한다
→ S-원리: 시작할 때 합의한 규칙을 기계가 그대로 집행한다
→ S-구조: 규칙 합의(돈 규칙 포함) → 앱 카메라 촬영 → AI 확인 → 마감 판정 → 장부 → 정산표 → 자동 알림
```

첫 버전 기능을 S코드와 R코드로 나눴다. S코드는 KP-1을 직접 바꾸는 것이다.

| 기능 | 분류 | 겨냥하는 것 |
|---|---|---|
| 목표 템플릿과 규칙 설정 (돈 규칙 포함) | S1 | KP-1, P11 |
| 사진 인증 + AI 확인 + 이의 제기 | S2 | KP-1 (확인) |
| 마감 자동 판정 | S3 | KP-1 (판정) |
| 벌금 장부 | S4 | KP-1 (계산) |
| **정산표와 탈퇴 처리 (조사로 추가)** | S5 | KP-1 (정산 안내), P3, P4 |
| 마감 전 알림, 정산 알림 | S6 | KP-1 (독촉), P8 |
| 쉬는 날, 복귀 축하, 지각 단계 | S7 | KP-2 |
| 그룹 현황 화면 | S 보조 | 서로 보는 눈을 유지한다 |
| 인증 카드와 한 주 격자 공유 | 성장 장치 | 핵심 문제와 관계없다. 사용자를 데려오는 역할이다 |
| 로그인, 그룹 만들기, 초대 | 기반 | 해당 없음 |

**발견**: 원래 첫 버전 기능 9개에는 **정산표(S5)가 없었다.** 실제 다툼이 가장 많이 나는 곳이 정산인데, 이를 겨냥한 기능이 빠져 있었다. 그래서 장부(6번)를 "장부 + 정산표 + 탈퇴 처리"로 넓힌다. (확정)

### 판단 상태
| 항목 | 상태 |
|---|---|
| 벌금 스터디가 규칙 집행을 사람이 한다 | 관찰된 사실 (모집글 10건) |
| 그것이 그룹이 깨지는 주된 원인이다 (KP-1) | 가설 |
| 방장이 도입을 결정한다 | 가설 (모집글을 방장이 쓴다는 점에서 추론) |
| 열품타와 충분히 다르다 | 외부 검증 |

### 확인이 필요한 질문
- 다음 설계를 가장 크게 바꾸는 질문: **방장들이 "총무 일을 덜어 주는 도구"에 반응하는가, 아니면 멤버들이 "습관 앱"으로 먼저 찾아오는가?** 사람 없이 지금 할 수 있는 시험은 없다. 홍보를 시작할 때 방장용 문구와 멤버용 문구를 나눠 올려서 비교한다.

## 1-2. 전략 정리 (planning-thinking-partner 형식)

### 내려가기: 원인 사다리
```
땅    : 벌금 스터디가 몇 주 안에 흐지부지되거나 다툼으로 깨진다
WHY 1 : 멤버가 빠지고, 벌금을 안 내고, 나갈 때 돈 문제로 다툰다
WHY 2 : 확인, 계산, 독촉을 사람이 하니 담당자가 지치고, 돈 규칙이 말로만 합의되어 있다
WHY 3 : 규칙을 집행할 도구가 없어서, 집행이 사람의 의지와 관계에 기댄다
땅속  : 규칙 집행의 주체가 사람이다 (KP-1, 가설)

다른 갈래: 규칙이 첫 실패에 너무 가혹하다 → 첫 실패가 포기로 이어진다 (KP-2, 가설)
```

### 올라가기: 원인에서 기능까지
| 원인 | 개입 원칙 | 누가 바꾸나 | 장치 | 사용자 흐름 | 기능 | 결과 지표 |
|---|---|---|---|---|---|---|
| 집행 주체가 사람 (KP-1) | 시작할 때 합의한 규칙을 기계가 집행한다 | 꼬박 | 자동 확인, 판정, 장부 | 방장이 규칙 설정 → 멤버는 촬영만 | S1~S4, S6 | 방장 수작업 횟수, 4주 유지율 |
| 돈 규칙이 불명확 (P11) | 돈 규칙을 참여 전에 보여 주고 동의받는다 | 꼬박 + 방장 | 규칙 카드, 정산표 | 초대 링크에서 규칙 확인 → 참여 | S1, S5 | 탈퇴 시 이의 제기 수 |

### 판 안의 자리: 선수 대신 판을 여는 쪽이 될 수 있는가
벌금 스터디는 인프런, 링커리어, 오픈채팅에 모집글을 올려 사람을 모은다. 방장이 꼬박에서 규칙을 만든 뒤 **초대 링크를 모집글에 그대로 붙이면**, 링크를 연 사람은 벌금, 보증금, 탈퇴 규칙을 보고 바로 참여한다. 그러면 모집글 하나하나가 꼬박 홍보가 된다.
- 확정된 "초대용 웹 화면"에 규칙 카드만 더하면 되므로 추가 작업이 작다.
- 모르는 사람끼리 모이는 "공개 챌린지"와는 다르다. 모집은 여전히 방장이 밖에서 한다. 그래서 공개 챌린지를 빼기로 한 확정 결정과 부딪히지 않는다.
- 상태: 확정

### P코드와 S코드 렌즈 (낯설게 보기와 공감)
- **낯설게 보기**: 벌금 스터디의 진짜 적은 게으름이 아니라 총무 일이다. (근거: 담당 교대 규칙, 노션 템플릿 구매)
- **공감**
  - 방장에게: "이번 스터디는 총무 안 하셔도 됩니다."
  - 멤버에게: "깜박해도 내일 돌아오면 됩니다."

### X=Y 은유 (한 문장 포지셔닝)

### 가설 카드 (KP-1)
- 문장: 우리는 벌금 스터디 방장과 멤버가 규칙 집행 부담 때문에 그룹이 깨진다고 믿는다. 왜냐하면 확인, 계산, 독촉을 사람이 하면 담당자가 지치고 돈 다툼이 생기기 때문이다.
- 지금 있는 근거: 공개 모집글 10건의 담당 교대 규칙, 노션 템플릿 판매, 미납과 탈퇴 다툼 후기 2건
- 다른 설명: 목표 자체가 너무 어렵다. 시험이 끝나서 자연스럽게 해산한다. 멤버의 동기가 처음부터 약했다.
- 틀렸다고 판단할 조건: 방장 수작업이 0에 가까운데도 4주 유지율이 단톡방 방식과 다르지 않다
- 가장 싸고 알맞은 시험: 3주차 지인 테스트에서 그룹이 깨질 때마다 이유를 기록한다 (시험 종료, 동기 부족, 돈 다툼, 귀찮음)
- 성공 지표: 4주 유지 그룹 비율. 보조 지표: 방장 업무량, 이의 제기 비율
- 맞으면: 정산과 탈퇴 처리 기능을 더 다듬는다
- 틀리면: KP-2(가혹한 규칙)나 동기 부족 쪽으로 무게를 옮긴다

### 4-2. 원리를 섞은 대안 세 가지
**대안 A. 다시 돌아오기 쉬운 그룹** (핵심 문제 후보 2: 한 번 빠지면 포기함)
| 겹 | 원천 (종류) | 원리 | 새로 가능해지는 것 | 순서 |
|---|---|---|---|---|
| 1 | 24 Hour Fitness (운영 원리) | 빠진 다음 날 돌아오면 따로 축하 | 깜박이가 이틀 연속 빠지는 것을 막는다 | 첫 버전 |
| 2 | 듀오링고 보호권 (감성·표현) | 한 달에 N번 쓰는 쉬는 날 | 아플 때 억울한 벌금 없이 기록을 지킨다 | 첫 버전 |
| 3 | 새 출발 효과 (이야기 구조) | 매주 월요일에 새 시즌 시작 | 지난주를 망친 사람도 다시 시작할 계기가 생긴다 | 운영 2~4주차 |

공식: 다시 돌아오기 쉬운 그룹 = 복귀 보상 + 쉬는 날 + 주간 시즌
판정: 더하기. 세 장치가 각자 따로 작동한다.

**대안 B. 벌금을 상금으로** (돈과 관계의 부담)
| 겹 | 원천 (종류) | 원리 | 새로 가능해지는 것 | 순서 |
|---|---|---|---|---|
| 1 | DietBet (사업 모델 뼈대) | 깜박이 벌금을 이번 시즌 꼬박이 몫으로 나눠 계산해 보여 준다 | 벌금이 "가격"이 아니라 "친구에게 지는 돈"이 된다 | 첫 버전 |
| 2 | 모임통장, 칠레 실험 (운영 원리) | 정산 알림을 앱이 자동으로 보낸다 | 친구끼리 독촉하지 않아도 된다 | 첫 버전 |
| 3 | 연대 책임 제거 (관계·조직 구조) | 한 사람의 실패로 그룹 전체가 벌받지 않는다 | 부담 때문에 그룹을 떠나는 사람이 줄어든다 | 첫 버전 (규칙으로만 지킴) |

공식: 벌금을 상금으로 = 목표 달성자 분배 + 자동 정산 알림 + 개인 책임
참고: 실제 벌금 스터디가 이미 상위자 분배를 하고 있다(모집글 1번, 2번). 그래서 이 대안은 새 행동을 만드는 것이 아니라 **이미 있는 행동을 자동화하는 것**이다. 위험이 가장 낮다.
판정: 곱하기. 깜박이 벌금이 꼬박이 몫으로 흐른다. 그래서 꼬박이는 계속할 이유가 커지고, 깜박이는 친구에게 지는 느낌이 커진다. 실제 돈은 앱 밖에서 그룹이 직접 정산한다.

**대안 C. 확인 없이 믿을 수 있고, 저절로 퍼지는 그룹** (확인 비용 + 퍼져 나가기)
| 겹 | 원천 (종류) | 원리 | 새로 가능해지는 것 | 순서 |
|---|---|---|---|---|
| 1 | 덴마크 세무조사 (운영 원리) | 앱 카메라로만 찍고 촬영 시각을 남긴다 | AI가 놓쳐도 옛날 사진 재사용이 막힌다 | 첫 버전 |
| 2 | BeReal (운영 원리) | 내가 인증해야 그룹원의 사진이 보인다 | 남의 사진을 보러 들어온 사람이 인증까지 하게 된다 | 첫 버전 |
| 3 | Wordle 격자 (감성·표현) | 그룹의 한 주를 칸 모양으로 요약해 공유한다 | 단톡방과 SNS에 꼬박이 자연스럽게 노출된다 | 첫 버전 (SNS 카드에 추가) |
| 4 | 행동 확산 실험, AA (관계·조직 구조) | 한 사람이 여러 그룹에 쉽게 들어가고, 새 그룹을 쉽게 연다 | 그룹 하나가 다른 그룹을 낳는다 | 운영 3~6주차 |

공식: 저절로 퍼지는 그룹 = 기계 기록 확인 + 먼저 올려야 보기 + 결과 격자 공유 + 겹치는 그룹
판정: 곱하기. 보고 싶은 마음이 인증을 부르고, 인증 결과가 공유되고, 공유를 본 사람이 새 그룹을 만든다.

### 4-3. 대안을 섞을 때 생기는 충돌
| 충돌 | 영향 | 권장 해결 | 상태 |
|---|---|---|---|
| 쉬는 날(A) vs 벌금 압력(B) | 쉬는 날이 많으면 벌금이 의미 없어진다 | 한 달 2번으로 제한하고, 그룹장이 0~3번 사이로 정한다 | 확정 |
| 먼저 올려야 보기(C) vs 그룹 현황 화면 | 현황 화면은 누가 인증했는지 보여 줘야 압력이 생긴다 | 누가 했는지는 항상 보이고, 사진 내용만 내가 인증한 뒤에 보인다 | 확정 |
| 벌금을 꼬박이 몫으로(B) vs 친구 관계 | 친구 돈을 내가 갖는 느낌이 불편할 수 있다 | 그룹을 만들 때 "꼬박이 몫으로 나누기", "공동 비용(회식비 등)으로 쓰기", "전원에게 똑같이 돌려주기" 중 하나를 고르게 한다 | 확정 |
| 첫 버전 기능 추가 vs 4주 일정 | 겹을 더할수록 일정이 밀린다 | 첫 버전에 넣는 겹은 계산과 표시만 바꾸는 것으로 한정한다 (A1, A2, B1, B2, C1, C2, C3). A3와 C4는 운영 중에 붙인다 | 확정 |

- "자동 확인, 판정, 장부를 한 번에 해 주는 곳은 없다" → 열품타 그룹 미션 확인 필요로 바뀜
